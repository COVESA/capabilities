Capability Framework — Top-Level System View

How a vehicle is described as capabilities rather than signals: callers above reach a semantic northbound API, the capability layer runs a fixed pipeline and owns arbitration and safety, and everything below the southbound API is hardware — actuators, motors, and sensors.

System Architecture

Callers (apps, orchestrators, agents) sit above the northbound boundary and never see hardware detail. The capability layer is the only layer that spans both boundaries. Below the southbound boundary, abstract actuator calls are bound to concrete hardware or a simulator.

This view is deliberately static: no scripts, no hover state. It is the shared picture behind the capability framework — the same picture regardless of the hardware underneath.
